# AI mandatory rules

- You may not modify files or the database without explicit permission; ask first.
- As long as no important information is lost, explain in fewer words, so a human can review it more easily.
- **Repo knowledge belongs in guidelines, not in user-level memories.** Conventions, decisions and reusable patterns go in `.ai/guidelines/*.md` (versioned, shared by the team) and are regenerated with `php artisan boost:update`; user memories only help you. If something is worth remembering for the project, edit the matching guideline instead of saving a memory.
- Check the current official documentation before implementing.
- If you cannot verify what you are about to implement, do not implement it.
- For pure implementation work (writing/editing code), spawn a subagent running sonnet/terra (`model: sonnet`/``model: terra`) to do the coding.
- **All code comments and documentation are written in English.** The only exception is a domain term that loses meaning in translation: keep the original and explain it in English next to it, never translate it halfway. What does **not** change is what you comment: comments in this project explain the **why** behind a decision, not what the code does, and that matters more than the language. This also covers `@param`, `@return` and other annotations, exception messages in code, and test names.
- **Every user-facing string is translatable, with the key in English.** The interface speaks the locales listed in `App\Support\SupportedLocale`, with English as the default: use `__('Save settings')` in Blade and PHP, with one JSON catalog per non-English locale under `lang/`, never a loose literal. The patient-facing labels in `app/Catalog` carry every supported language inside the enum itself, and the official LOINC term is not translated (ADR 0005). The active locale comes from `App\Support\SupportedLocale`, which is the closed list, and is stored in the clear in `users.locale`: a deliberate exception to encryption, documented in `docs/adr/0007-encrypted-user-configuration.md`. See `docs/adding-a-language.md` before adding another locale.
- **Every clinical numeric field uses `type="number" min="0" step="any" inputmode="decimal"`, never `type="text"`.** With text you can type `7,8` or `7.8`, and that decimal-separator ambiguity is a parsing error you cannot fix after the fact on encrypted data. `step="any"` accepts decimals and still steps by one with the arrow keys (`step="1"` would mark `7.5` as invalid). The 2-decimal limit is enforced by the client in `resources/js/health/numericValue.js` (`parseNumericValue`), not by the browser; the value is still stored as a string (ADR 0004).
